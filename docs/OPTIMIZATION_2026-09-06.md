# ScholarForge 主流程修复与验收（2026-09-06）

基线：`8e1bd3ebac80dcfafba2102573bb0411402e6c20`。本轮针对产品审查中已确认的主流程、文献、编辑保存、套餐、交付和模型分工问题实施；不进行外网部署，不改写真实用户论文。

## 已实施

- 修复完整论文页面初始化异常、章节成功后未定义变量异常，以及文献确认后未保存的问题。
- 同页检索和选择文献；确认后自动生成大纲，大纲确认后进入首章，保存并确认当前章后自动生成下一章。每章仍需用户确认，不自动确认正文。
- 大纲和章节确认均提交当前编辑内容；编辑、重写、返回章节后撤销相关确认与旧全文检查。刷新生成中的页面会恢复轮询。
- 新流程只接受服务端签名的检索记录；手填记录通过学术数据源查找并匹配标题/DOI，使用上游规范记录替换自填元数据。前端填写来源名称不能伪造核验状态。
- 参考文献由核验记录统一编排，不让模型单独生成参考文献章节。已有正文时禁止重排/替换文献，避免原编号指向另一篇论文。
- 最终检查覆盖非空、缺章、逐章确认、大纲顺序、长段落重复、单号/列表/范围引用、未解析占位符、模型自行编写的文献列表；导出绑定内容指纹，防复用过期通过结果。
- 同版本重复下载复用现有 Word；同进程相同导出请求合并执行。首次章节初始化使用数据库条件写，章节工作使用条件抢占，避免初始化覆盖另一请求的进行中状态。
- 套餐权益明确展示，首次生成失败也保留已付费订单；同项目后续章节复用，重写须使用已绑定本项目的订单；每章最多 3 次成功重写，技术失败保留原稿和次数。
- 异步大纲回写核对起始大纲、版本和资料快照，检测到新编辑则保留最新内容并明确报错。通用工具不能绕过完整流程直接生成全文。
- 专家服务同页跳转，传项目 ID，课程页和需求表带入题目、学科和写作要求；专家服务单独报价。
- 模型后台增加通用/理工/人文社科的主写及独立审校角色配置；审校和修订均接收证据上下文，统计含修订的 token 与耗时。不再硬编码未经本项目实测的厂商优势；无第二模型时跳过独立模型审校。
- 结果章节不再用文献年份/被引次数图凑数；这类统计只用于综述。未改变原论文测量数值，不把缺少实验资料当作已有实验。
- 修正首页未经核验示例的表述、最近项目继续入口、循环步骤条、窄屏按钮换行、创作目的弹窗焦点与键盘行为、删除按钮可访问名称，以及开发模板演示提示。
- 修复离线质量评测能被个别 `mode: live` 用例覆盖的问题：离线标志强制使用 fixture/内置引擎，不可调用真实模型；mock 冒烟日志不再输出登录 token。

## 边界与后续验收

1. 本轮不是“所有功能已达到理想状态”的证明：真实多模型盲评、各学科长篇质量、逐论断与原文证据对应关系、支付渠道真实回调、跨实例压力测试尚未完成。可核验论文存在不代表引用支持正文的每个观点。
2. 服务端签名依赖稳定的 `JWT_SECRET`。旧完整流程项目若没有签名，需要从“重新核验文献”补核验；已有正文暂不支持更换大纲结构或文献顺序，应新建项目保留旧稿，不做自动破坏性迁移。
3. 仍需用户核对论文和图表来源、数据集/指标是否可比、授权范围和学术诚信；不得为贴合上下文篡改原论文数值。
4. 新模型策略是可配置分工，不承诺优于单模型。建议准备各学科代表性样例，分别评估证据支持、结构、语言、成本、时延和失败率，再设置默认组合。
5. Docker Desktop 本轮查询引擎返回 HTTP 500，未重新构建镜像。Python 可选完整模式依赖解析、Quarto 多格式导出本轮未重新验收；相关原有 CI 门禁保留。
6. 仓库 CI 对 `master` 推送和 PR 运行测试/构建，配置中没有镜像发布或自动部署步骤。Docker Compose 从调用目录构建；外部部署主机运行的提交仍需单独检查。本轮不发布外网服务。
