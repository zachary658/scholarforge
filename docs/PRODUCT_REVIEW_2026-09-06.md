## 核查范围与证据边界

检查了前端路由、导航、工作台、完整论文流程、文献管理、通用生成器、专家服务、计费入口，以及后端工作流、章节生成、多模型编排、文献过滤、图表补充、全文检查和 CI/Docker 配置。重点深查用户从创建到交付的跨模块契约。其他后台与专业服务板块未逐接口完成运行验收。

前端 13 项现有测试通过，Vite 生产构建通过。通过本地静态预览实际查看首页和登录页。后端依赖不完整，缺少 better-sqlite3、@xmldom/xmldom 等，完整后端与端到端测试未通过；没有进行真实模型质量评测、实际支付或部署验收。静态预览没有后端，页面显示的“暂未上架”不能视作真实业务数据结论。浏览器 CLI 未在 PATH 中找到，页面观察使用内置浏览器完成。

用源码转换与模拟依赖进行了隔离执行，不触碰业务数据库，复现页面初始化异常、章节完成后异常、文献未保存及引文范围误判。隔离执行不等同于真实端到端通过。

## 已确认的问题

### P0：全文流程存在直接阻断

1. `client/src/pages/PaperWorkflow.jsx:118`：effect 依赖数组读取 currentIdx、curChapter，而声明在 257–258 行。首次执行组件即抛出 `Cannot access 'currentIdx' before initialization`。需要提前声明派生变量，并补页面挂载测试。
2. `server/src/services/workflow-service.js:170`：generateCurrentChapter 引用本函数不存在的 sources 和 verified。生成成功后仍抛出 `sources is not defined`，状态无法进入章节确认。对应文献保存代码应放在文献确认环节，状态推进和保存需要一致性保护。
3. `server/src/services/workflow-service.js:98`：confirmLiterature 过滤并检查请求中的文献，但没有保存到项目 sources。隔离执行确认保存函数未被调用。用户看到确认成功，后续却读取旧资料或空资料。

### P1：真实性与交付校验不足

4. `paper-distillation.js:319`：正文文献过滤信任客户端可填写的 source_db、doi/source_url；没有要求服务端保存的来源身份或核验结果。`PaperWorkflow.jsx:30` 的前端判断更宽，填任一来源字段就显示可溯源。不能把这些字段检查称作真实性验证。建议只确认属于本项目的服务端文献 ID；手工资料先核验，记录标题/作者/年份匹配、来源及核验时间，并统一前后端状态。
5. `workflow-service.js:214`：全文检查只检查已有章节 status，不检查全部 confirmed；章数/标题不匹配仅警告。引用 `[1-999]` 被识别后未展开，进入未使用的 unverifiable 数组，最终仍可能通过。隔离案例中只有 3 条参考文献、未确认章节和 `[1-999]`，passed 为 true。需要非空正文、章数一致、逐章确认、引用单号/列表/范围、证据 ID 及未解析占位符门禁。
6. 版本失效机制不完整：`chapter-service.js` 手工编辑会清 final_check_json，但重写没有清除；重写也保留 confirmed。`task-store.js:514` 保存大纲不清全文检查、不对旧章节做版本匹配。建议大纲、章节、证据包、最终检查与导出绑定版本；修改后撤销相关确认与检查。检查通过只对当时版本有效。
7. 更正初步审查判断：`ai-service.js` 的审校提示已经通过公共 ctx 注入 references，不能认定审校完全没有文献。实际不足在于修订路径遗漏 ctx、编排未完整传递资料表和章节上下文，以及未明确说明 `[CITE:n]` 是合法的单章占位符。应补齐这些传递与说明，并在修订后执行规则检查。

### P1：编辑、自动推进与订单体验

8. 大纲“确认”仅确认服务器已保存版本，不提交当前编辑缓冲；章节“确认”也不会保存 textarea。用户可误确认旧内容。建议“保存并确认”为一个有版本校验的动作，提供未保存提示。
9. `PaperWorkflow.jsx:297` 重写只把操作传给 integrity.ensure；已同意承诺时 ensure 返回 true，不执行回调，函数随后结束，因此重写按钮无动作。需要和初次生成采用一致的执行模式。
10. 主流程仍以新标签页跳转文献检索和大纲生成；“深度文献检索”实际指向文献综述生成页。大纲/章节确认后只是换步骤，仍需再点生成。建议把检索和大纲生成嵌入工作流，确认后自动发起下一章，失败时停留当前章并可恢复。
11. 项目订单复用已存在，但尚无统一可见套餐权益说明。完成后允许返回章节，而当前章生成路径拒绝 completed 订单，重写路径却允许，入口行为不一致。重写失败前已清空旧内容并递增次数。建议先展示套餐范围/剩余次数/有效期；失败保留上一版，技术失败不占有效重写次数。
12. `Courses.jsx` 不读取工作流传入的 projectId/title/field 等参数。专家链接看似携带上下文，实际接单页没有承接。建议通过项目 ID 拉取资料、预填诉求并明确人工服务内容；避免将完整写作要求放 URL。

### P2：设计与生成质量

13. 首页实际可见“10 分钟出稿”及硬编码示例文献“张伟、李娜……计算机学报，2023”，并标注“真实文献（可溯源）”，没有回查链接。此处未验证该文献是否存在，不能断言其虚假；但演示数据不应作为已核验成果展示。建议真实可点开的样例、来源面板与生成耗时区间，逐章确认的用户等待时间不应计成固定交付承诺。
14. 工作台仍同时展示完整流程、AI 论文写作和大量工具卡片；最近论文“继续”跳到项目列表，没带项目 ID。建议首页主要动作是“继续当前论文”和“新建论文”，各项目展示当前步骤、下一动作、未完成原因，独立工具为次级入口。
15. 工作流把“生成章节”和“单章确认”列为两个线性步骤，逐章循环会令步骤条反复后退。建议合为“正文（第 n/m 章）”，另列章节状态。记住创作目的仅写 localStorage 未读取；全文检查状态也没有从服务器恢复到本地显示。
16. `ensureGroundedVisuals` 对结果/分析章节补图时，资料不足会添加参考论文年份分布/引用次数图，并可能在多个章节重复插入相同资料表。这些图真实也不等于支持当前论点。建议先建图表计划：论点、数据来源、单位、适用章节；文献统计只用于综述，缺实验数据应提示补充。不得为贴合上下文修改原论文测量数值。
17. 多模型策略仍为学科关键词和固定模型 key 顺序；planner 只记录、不执行。没有基于本项目样例的优势评测，不能证明质量优于单模型。单模型时也仍执行审校，与注释不符；修订调用 tokens 未计入返回总量。建议保留简单编排，补任务级角色配置、盲评、时延和全调用成本统计，再调整路由。

## 工程与上线条件

CI 已覆盖 master 推送/PR、服务端测试、smoke、前端测试/构建、Python 依赖策略及 Docker 构建。依赖策略脚本和配置都在 master。仓库工作流没有镜像发布和生产部署步骤；docker compose 从当前本地目录构建，不能据此确认外部服务器在运行哪一个提交。

现有前端测试没有挂载完整流程组件，服务端测试/smoke 未找到新流程和编排的完整行为覆盖。建议先加静态未定义变量检查与流程挂载测试，再覆盖：检索保存→大纲保存确认→订单复用→首章确认→下一章→重写失败恢复→最终检查→导出→专家承接。质量门禁的 mock 评测不能替代真实模型盲评。

## 建议实施顺序与验收

1. 修通 P0 与编辑/确认错误。验收：新项目可连续完成两章，刷新不丢状态，不重复收费。
2. 补可信文献与版本化交付门禁。验收：伪造来源字段、越界范围引用、未确认章节、旧检查均不能作为正式交付放行。
3. 整合单页流程、项目套餐、专家承接。验收：用户能在同一流程继续，看到权益，专家页自动带入项目。
4. 优化图表计划、学科模板与模型评测。验收：抽样核对每张图和每条关键论断的来源，并比较质量、失败率、时延和成本。
5. 最后统一视觉层级、移动端和键盘可访问性；登录后页面与真实生成需在依赖修复的测试环境再做实际体验验收。
